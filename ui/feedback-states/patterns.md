# Feedback States — Patterns

模式用「结构 + 状态 + 时机 + 文案」描述，框架无关。

---

## 1. Button busy（按钮忙态）

**用途：** 防止重复提交，并告诉用户「正在处理」。

### 结构

```
idle:    [ 提交 ]
pending: [ ◌ 提交中… ]  ← 禁用或 aria-disabled
success: [ ✓ 已提交 ]   ← 可选，短驻后回到 idle / 跳转
```

- 主按钮进入 busy：显示 spinner 或文案切换；**点击无效**
- 同源表单内其它提交入口一并锁定
- 需要时可保留「取消」为唯一可点出口

### 状态

| State | 行为 |
|-------|------|
| `idle` | 可点 |
| `pending` | 锁定；最短展示 300–400ms |
| `success` | 可选短成功态，再导航或复位 |
| `error` | 解锁；错误交给 Inline / Toast |

### 实现要点

- `type="submit"` + 请求 in-flight 标志；勿只靠 CSS 禁用却仍触发
- 键盘：busy 时不可再被 Enter 重复提交
- 成功跳转前不必强留成功态；同页反馈则短驻 `800–1200ms`

## 2. Skeleton / loading（骨架与加载）

**用途：** 异步内容未到时保持布局稳定，降低空白焦虑。

### 结构

```
┌─────────────────────────┐
│ ████  ██████            │  ← 与最终布局同构的灰块
│ ████████████████        │
│ ████████  ██████        │
└─────────────────────────┘
```

- **优先骨架**（列表行、卡片轮廓），次选居中 spinner
- 骨架形状贴近真实内容（头像圆、标题条、两行正文）
- 局部加载用局部骨架，避免整页替换已有内容

### 状态

| State | 行为 |
|-------|------|
| `idle` | 有缓存可先画缓存 |
| `loading` | 延迟 150–200ms 后出骨架 |
| `ready` | 内容替换；可短淡入 |
| `error` | 转 Error+retry，勿无限骨架 |

### 实现要点

- 动画用轻脉冲 / shimmer；`prefers-reduced-motion` 改为静态块
- 列表分页：「底部加载更多」用小条，不重刷整表骨架
- 与 Empty 互斥：`ready && length===0` 才空态

## 3. Optimistic update（乐观更新）

**用途：** 低风险、高频率操作（开关、点赞、标星、勾选）先改 UI。

### 结构

```
tap → UI 立即变为目标态
    → 请求中（可无全局 busy）
    → 成功：保持
    → 失败：回滚 UI + Toast 说明
```

### 状态

| State | 行为 |
|-------|------|
| `confirmed` | 与服务器一致 |
| `optimistic` | UI 已变，等待确认 |
| `rolled_back` | 恢复旧值 + 错误反馈 |

### 实现要点

- 只用于可逆、冲突代价低的操作；支付/删库等不要乐观
- 回滚必须**让用户知道失败了**
- 连续快速切换：以最后一次意图为准，取消过期请求

## 4. Toast / Snackbar（全局短反馈）

**用途：** 不打断当前上下文的成功/失败告知。

### 结构

```
┌──────────────────────────────────────┐
│ ✓ 已保存          [撤销]        ✕   │  ← 成功可带次要动作
└──────────────────────────────────────┘
┌──────────────────────────────────────┐
│ ! 发送失败：网络超时       [重试]    │  ← 错误更久或手动关
└──────────────────────────────────────┘
```

- 位置：移动偏底部；桌面偏右上或底部居中（项目统一即可）
- 成功可自动消失；**错误建议更久或常驻到关闭**
- 可选动作：撤销、重试、查看

### 状态

| State | 行为 |
|-------|------|
| `queued` | 多条时替换或最多叠 1–3 条 |
| `visible` | 计时或等待动作 |
| `leaving` | 短退场动画 |

### 实现要点

- `role="status"`（成功）/ `role="alert"`（错误）+ `aria-live`
- 勿用 Toast 承载长表单错误（改 Inline）
- 不挡 FAB / 主 CTA；留安全边距

## 5. Empty state（空状态）

**用途：** 合法地「没有数据」，引导下一步，而非报错。

### 结构

```
[ 插图可选 ]
标题：还没有运单
说明：创建后会出现在这里
[ 主行动：创建运单 ]   [ 次要：了解规则 ]
```

- 必有：**标题 + 一句说明 + 至少一个行动**（或解释为何无行动）
- 区分「从未有过」vs「筛选结果为空」（后者行动应是「清空筛选」）

### 状态

| State | 行为 |
|-------|------|
| `empty-default` | 无数据引导创建 |
| `empty-filter` | 无匹配，引导改筛选 |
| `empty-permission` | 无权限，引导申请/切换账号 |

### 实现要点

- 不要对空态自动 Toast
- 插图克制；无插图也成立
- 与 Error 分开：空是 0 结果，错是请求失败

---

## 6. Error + retry（错误与重试）

**用途：** 加载或操作失败后，保留上下文并给出恢复路径。

### 结构

```
┌─ 列表区域 ─────────────────────────┐
│  [!] 无法加载运单                   │
│  网络超时 · 请检查网络后重试         │
│  [ 重试 ]    [ 查看详情 ]            │
└────────────────────────────────────┘
```

- 区块级错误画在**内容槽**内，尽量保留页头/导航
- 文案：现象 + 可能原因（若已知）+ 行动
- 重试使用原请求参数；可显示上次失败时间

### 状态

| State | 行为 |
|-------|------|
| `error` | 展示原因与 CTA |
| `retrying` | 按钮 busy + 可再骨架 |
| `recovered` | 进入 ready / empty |

### 实现要点

- 4xx/5xx/网络断开文案区分（至少网络 vs 服务器）
- 幂等写操作重试要安全；非幂等需确认或换「刷新状态」
- 全局致命错误可用整页；默认可恢复错误用区块

## 7. Inline result（行内结果）

**用途：** 字段或列表行旁的即时反馈，不抢全局注意力。

### 结构

```
昵称  [____________]  ✓ 已保存
邮箱  [____________]  ! 格式不正确
行项目 …             [保存中…] → ✓
```

- 成功：短勾或「已保存」，`1.5–2.5s` 后可淡出
- 失败：错误文案紧贴字段，色 + 图标；焦点可移到首个错误
- 适合自动保存、行内编辑、设置项

### 实现要点

- 与 Toast 二选一为主，避免同消息双报
- 错误文案关联 `aria-describedby`
- 多个字段错误时汇总一条可选，但字段旁仍要标

## 8. Long-running progress（长耗时进度）

**用途：** 导出、上传、批量处理等超过数秒的任务。

### 结构

```
┌─────────────────────────────────────┐
│ 正在导出报表                         │
│ ████████░░░░  62%                    │
│ 已处理 620 / 1000                    │
│ [ 取消 ]                             │
└─────────────────────────────────────┘
```

- 不确定时长：用不确定进度条 + 阶段文案（「打包中…」）
- 可取消则提供取消，并定义取消后的 UI（部分成功？）
- 完成后：关闭进度 + 成功 Toast（含下载链接若适用）

### 状态

| State | 行为 |
|-------|------|
| `running` | 进度 / 阶段 |
| `cancelling` | 等待服务端确认取消 |
| `done` / `failed` | 终态反馈 |

### 实现要点

- 切换页面时：后台任务用全局入口（顶栏小进度），勿默默丢失
- 失败保留「再试一次」与已生成部分结果（若有）

## 9. Destructive confirm（危险确认）

**用途：** 不可轻易撤销或代价高的操作（永久删除、清空、解绑、转账）在执行前拦截。

### 变体 A — 对话框 / Sheet 按钮确认

### 结构

```
┌──────── 确认对话框 / Sheet ────────┐
│ 标题：删除运单 #A2048？              │
│ 说明：将无法恢复，相关轨迹一并移除。   │
│                                    │
│  [ 取消 ]              [ 删除 ]     │
│   ↑ 默认焦点            ↑ 危险样式   │
└────────────────────────────────────┘
```

- 说清：**对象是谁** + **后果** + **是否可恢复**
- 主危险按钮用破坏性样式（红/实心危险）；**默认焦点在「取消」**
- 极高危可要求输入名称 / 勾选「我了解后果」（少用，避免疲劳）

### 变体 B — 滑块拉满确认（Slide to confirm）

**规格：** 确认或删除必须把滑块拉满；松手未满则自动回弹到 0，不触发操作。

```
┌─────────────────────────────────────────┐
│  删除此仓库（无法恢复）                    │
│  ┌───────────────────────────────────┐  │
│  │ ●========░░░░  滑到底以确认删除     │  │
│  └───────────────────────────────────┘  │
│  progress = 0 … 1；≥ 阈值才 commit        │
└─────────────────────────────────────────┘
```

- 轨道为横向（也可竖向，规则相同）
- 拇指跟手拖动；**松手时**：
  - `progress >= 0.95`（建议阈值 95–100%）→ 吸满到 1 → 触发确认
  - 否则 → **动画回弹到 0**，不调用危险操作
- 拉满瞬间可短震动 / 变色（危险底），再进入 Button busy 或直接执行
- 文案写在轨道上：「滑到底以确认删除」；拉满后可变为「已确认」

### 状态（滑块）

| State | 行为 |
|-------|------|
| `idle` | progress = 0 |
| `dragging` | 跟手，无提交 |
| `snap_back` | 未满松手 → 回弹 0 |
| `armed` / `committed` | 达阈值 → 锁定滑块 → 执行操作 |
| `reset` | 失败或取消后复位到 0，可再滑 |

### 状态（对话框变体）

| State | 行为 |
|-------|------|
| `open` | 遮罩 + 焦点陷阱；Esc / 取消关闭 |
| `confirming` | 点危险钮后可 Button busy |
| `closed` | 焦点回到触发控件 |

### 实现要点

- 可恢复删除优先用 **Undo window**，不必每次弹确认
- 移动端：对话框可用 bottom sheet；**滑块**更适合「防误触删除」且不依赖二次点击
- 滑块：`touch-action: none`；用 pointer 事件；阈值判断在 `pointerup`
- 回弹：`200–280ms` ease-out；`prefers-reduced-motion` 可瞬移回 0，但仍禁止未满提交
- 键盘可达：滑块旁提供「按住空格确认」或改走对话框变体，避免只靠拖拽
- 确认后走既有 busy / Toast / error 路径；成功后滑块可禁用或整段卸下

### 选型

| 场景 | 更合适 |
|------|--------|
| 普通危险（删一条） | 对话框按钮确认 |
| 极高误触代价（清空、注销、删库） | **滑满确认** |
| 可恢复删除 | Undo window，不是滑块 |

## 10. Page banner（页顶告警）

**用途：** 必须持续可见的系统级信息（维护、欠费、权限不足、只读模式）。

### 结构

```
┌─ banner（贴在主内容之上）──────────────────┐
│ ! 系统维护中 02:00–04:00，写入已暂停  [详情][✕] │
└────────────────────────────────────────────┘
│ 页面其余内容…                                │
```

- **不自动消失**；关闭策略：会话内 / 用户手动 / 条件恢复后自动撤
- 严重级：info / warn / critical（色 + 图标 + 文案，不单靠色）
- 可带 1 个主行动（去充值、查看公告）；次要为关闭

### 状态

| State | 行为 |
|-------|------|
| `visible` | 占布局或 sticky 顶 |
| `dismissed` | 按策略隐藏 |
| `resolved` | 根因消失后移除，勿残留 |

### 实现要点

- 勿用 Toast 代替 Banner（用户错过就没了）
- 多条 Banner：最多同时 1–2 条，更高优先级覆盖或堆叠有序
- 读屏：`role="status"` 或区域标题；critical 可用 `alert`（慎用打断）

## 11. Undo window（限时撤销）

**用途：** 可恢复的破坏性操作（删除一行、归档、移出列表）先改 UI，倒计时内可撤销。

### 结构

```
列表：目标行先移除（或变淡出列）
底部/行内条：
┌─────────────────────────────────────────┐
│ 已删除「运单 #A2048」  ⏱ 5s   [ 撤销 ]   │
│ ████████░░░░  ← 倒计时进度               │
└─────────────────────────────────────────┘
到期 → 发送真实删除；点撤销 → 行恢复，取消请求
```

- **先更新 UI**，到期再 commit；撤销则恢复并 abort
- 时长 `5–8s`；展示剩余秒数或进度条
- 与 Toast 撤销的差别：Undo 窗更醒目、占位稳定，适合「刚删错」

### 状态

| State | 行为 |
|-------|------|
| `pending_commit` | UI 已变；计时中 |
| `undone` | 恢复 UI；不发或取消请求 |
| `committed` | 计时结束，真实提交 |
| `commit_failed` | 提交失败 → 行恢复 + Error Toast |

### 实现要点

- 到期与点击撤销必须互斥（用世代 token / aborted 标志）
- 连续删除：可合并为「已删除 N 项」一条 Undo，或队列（选一种并写清）
- 不可恢复操作不要假装 Undo

## 组合示例（页面级）

### A. 创建表单页

1. 点提交 → **Button busy**
2. 校验失败 → **Inline**（不上 Toast）
3. 网络成功 → 短成功态或跳转；若同页 → **Toast 成功**
4. 网络失败 → 解锁按钮 + **Toast/Inline 错误**

### B. 列表页

1. 首拉 → **Skeleton**（延迟出现）
2. 成功且空 → **Empty**
3. 失败 → **Error+retry**
4. 行内收藏 → **Optimistic** + 失败 Toast
5. 删一行（可恢复）→ **Undo window**
6. 清空全部（不可恢复）→ **Destructive confirm** → busy

### C. 设置开关

1. 切换 → **Optimistic**
2. 失败 → 回滚 + **Toast 错误**
3. 无全局转圈

### D. 系统状态

1. 维护 / 欠费 → **Page banner**
2. 单次操作结果仍用 Toast，不取代 Banner

## 文案模板（可改名词）

| 场景 | 示例 |
|------|------|
| 保存成功 | 已保存 |
| 删除成功 | 已删除。[撤销] |
| 确认删除 | 删除{对象}？此操作无法恢复。 |
| 确认取消 | 取消 |
| Banner 维护 | 系统维护中 {时段}，{影响}。[详情] |
| Undo 中 | 已删除「{名称}」。{n}s 内可撤销 |
| 网络失败 | 网络异常，请检查连接后重试 |
| 服务器失败 | 服务暂时不可用，请稍后重试 |
| 空列表 | 还没有{对象}。{行动}后会显示在这里 |
| 筛选为空 | 没有符合条件的结果。[清除筛选] |
| 加载中 | 加载中… / 骨架无文案也可 |

## 跨模式约定

| Topic | Rule |
|-------|------|
| 互斥 | 同一内容槽：loading / empty / error / data 四选一 |
| 队列 | Toast 同时最多 1–3；同类型可替换 |
| 确认 vs Undo | 不可恢复 → Confirm（按钮或滑满）；可恢复 → Undo window |
| Banner vs Toast | 持续系统态 → Banner；瞬时结果 → Toast |
| 皮肤 | 成功/错误色跟随**项目** token / 组件库主题；`demo.html` 仅为示意，落地勿复制 demo 配色；需图标或文字双通道 |
| 动效 | 反馈时长见 `SKILL.md` 时机表；可打断，以最新操作为准 |
| 测试 | 连点、慢 3G、失败、空数据、权限空、误删撤销、确认 Esc 七条路径 |
