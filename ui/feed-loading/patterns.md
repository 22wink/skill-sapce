# Feed Loading — Patterns

## 1. Feed skeleton reveal（信息流同构骨架 → 错开浮现）

**规格：** 做一个信息流加载：先显示和真实内容形状一样的骨架屏（例如描述部分样式：圆头像、标题条、图片块，尺寸和位置跟真实卡片一致），所有骨架屏共用一道柔和的斜向光带，每 1.5s 从左往右扫过；数据到了以后，按头像、标题、图片这些块从上到下每块错开 60ms 依次浮现（淡入+上移 8px），骨架同步淡出，整页不跳动、不闪白。

### 结构

```
Card slot（高度由骨架撑住，真卡叠在同槽）
┌─────────────────────────────────────┐
│ (●)  ████████                       │  ← 圆头像 + 标题条
│      ██████████                     │  ← 副标题条（可选）
│ ┌─────────────────────────────────┐ │
│ │         图片块                   │ │
│ └─────────────────────────────────┘ │
│ 共用斜向光带 ╱╱╱  每 1.5s 左→右       │
└─────────────────────────────────────┘

数据到：
  真·头像  → +0ms   fade + ↑8px
  真·标题  → +60ms
  真·图片  → +120ms
  骨架整卡 opacity → 0（同步开始淡出）
```

### 同构规则

| 真内容块 | 骨架块 | 要求 |
|----------|--------|------|
| 头像 | 圆（或同半径圆角） | 宽高、边距一致 |
| 标题 / 副文 | 圆角条 | 行高、宽度比例接近真文案占位 |
| 封面图 | 矩形块 | 宽高比与真图容器一致 |
| 操作行（可选） | 短条 / 圆钮 | 位置一致 |

列表多卡时：每卡内部结构同构；**光带动画全局共用一条时间线**（同一 `animation-delay: 0` 或同一 CSS 变量相位）。

### 光带

- 形态：柔和斜向高光（gradient，低对比，避免刺眼实线）
- 方向：从左往右扫过
- 周期：`1.5s` linear infinite（或等价）
- 作用域：盖在所有骨架块之上（可用列表级 `::after` / 统一 mask，避免每块各播各的）

### 状态

| State | 行为 |
|-------|------|
| `skeleton` | 只显示同构骨架 + 扫光；容器高度已是终态高度 |
| `revealing` | 真内容已就位（可 `visibility`/`opacity:0`）；分块 stagger 浮现；骨架淡出 |
| `ready` | 仅真内容；骨架卸载或 `pointer-events:none` 且不可见 |
| `empty` / `error` | 交给 `feedback-states`，不要停在半骨架 |

### 无跳动 / 不闪白

1. **同一槽**：骨架与真卡共用同一 card 容器尺寸，勿先 `display:none` 骨架再挂真卡导致 reflow 闪一下。
2. **先就位再显影**：真内容可在骨架下（或同层 opacity 0）完成布局，再做 fade/translate。
3. **底色连续**：容器背景与页面底一致或与卡面一致，切换时不要闪成白屏默认色。
4. **图片**：真图未 decode 前可继续露骨架图块，或用已占位的同尺寸空图，避免图片加载再撑高。

### 动效参数

| 项 | 值 |
|----|-----|
| 光带 | `1.5s`，左→右，循环 |
| Stagger | 块顺序自上而下，间隔 `60ms` |
| 块进入 | `opacity 0→1` + `translateY(8px→0)`，`~240ms` ease-out |
| 骨架退出 | `opacity 1→0`，与 revealing 重叠 |

### `prefers-reduced-motion`

- 停用光带与 stagger
- 数据到后：短淡入整卡或直接切 `ready`
- 仍保持同构占位，避免跳动

### 实现要点（框架无关）

- CSS：列表容器上的倾斜 `linear-gradient` + `transform: translateX` 动画；骨架区 `overflow: hidden`
- 真块：`animation-delay: calc(var(--i) * 60ms)`
- React/Vue：`status: 'skeleton' | 'revealing' | 'ready'`；revealing 时双层渲染一帧起动画
- 分页加载：仅对新插入的卡走一遍 skeleton→reveal，已有卡不要重扫闪白
- 与项目 UI：用库的 Skeleton/Avatar/Card 拼同构；光带与 stagger 用本契约覆盖默认脉冲

### 和 feedback-states 的分工

| 场景 | 用谁 |
|------|------|
| Feed / 卡片流首屏、分页显影 | **本 skill #1** |
| 商品列表触底预加载 | **本 skill #2** |
| 按钮 busy、Toast、Empty、Error+retry | `feedback-states` |
| 表单行内保存 | `feedback-states` Inline |

## 2. Product list prefetch（商品列表提前加载）

**规格：** 做一个商品列表，滑到离底部还剩约一屏时就提前加载下一页；底部显示 3 个依次跳到的小圆点；新商品卡片每张错开 50ms，从上方 24px 处滑上来并淡入，约 0.45s，像传送带接上；加载期间滚动不卡、位置不跳；最后一页显示“没有更多了”。

### 结构

```
┌─ scroll root（window 或列表容器）─────────────┐
│  [商品卡] [商品卡] …                          │
│  [商品卡] …                                   │
│                                               │
│  ↕ 剩余可滚距离 ≤ ≈1× viewport 高度            │
│    → fetch next page（若 !loading && hasMore） │
│                                               │
│  footer:                                      │
│    loading →  ● ● ●  依次跳                    │
│    end     →  没有更多了                       │
└───────────────────────────────────────────────┘

新卡进入（仅本页新节点）:
  card[i]: delay = i * 50ms
  from: opacity 0 + translateY(-24px)   ← 在上方 24px
  to:   opacity 1 + translateY(0)
  duration ≈ 0.45s
```

### 预加载阈值

- 计算：`distanceToBottom = scrollHeight - scrollTop - clientHeight`
- 触发：`distanceToBottom <= clientHeight`（约一屏；可 `0.9–1.1` 倍微调，默认 **1 屏**）
- 必须有 **in-flight 锁**：loading 中不重复请求
- `hasMore === false` 后不再监听触发

### 底部三点

```
( ● ) ( ● ) ( ● )   ← 垂直跳动，相位依次错开（如 0 / 0.15s / 0.3s）
```

- 仅 `loading` 时显示
- 柔和、小尺寸；不挡点击（`pointer-events: none` 于动画层）

### 传送带接卡

| 项 | 值 |
|----|-----|
| 作用对象 | **本批新追加**的卡片，已在屏上的旧卡不动 |
| Stagger | 每张 `+50ms` |
| 位移 | 从上方 `24px`（`translateY(-24px)` → `0`）滑入 |
| 透明度 | `0 → 1` |
| 时长 | **约 0.45s**，ease-out |
| 体感 | 像传送带一节节接上，而非整页闪入 |

### 滚动不卡、位置不跳

1. **只 append**，禁止整表 `innerHTML` 重绘或 key 大面积打乱导致 remount
2. **不写** `scrollTop`（除非用户主动点「回到顶部」）
3. Footer 常驻高度槽：loading / 末页文案切换时高度接近，避免脚垫忽高忽低猛跳
4. 图片：定高或 `aspect-ratio`，防解码后撑开把视口顶飞
5. 长列表可考虑虚拟列表，但接入动画只打在「新挂载行」；虚拟化时勿在加载瞬间校正错位

### 状态

| State | 行为 |
|-------|------|
| `idle` | 有数据；未在请求 |
| `loading` | 显示三点；可继续滚 |
| `appending` | 新卡带传送带动画接入 |
| `end` | 文案「没有更多了」；断开预加载 |
| `error` | 脚注重试（可用 feedback-states）；不清空已有列表 |

### `prefers-reduced-motion`

- 三点改为静态或极弱闪烁
- 新卡：短淡入或直接出现，取消 24px / 0.45s 位移
- 预加载阈值与「没有更多了」不变

### 实现要点

- `scroll` 监听用 `requestAnimationFrame` 节流，或 `IntersectionObserver` 哨兵放在「底上一屏」位置
- 哨兵方案：列表末尾上方插入高度约 `100vh` 的不可见 sentinel，intersect 即加载（等价「剩一屏」）
- 分页：`page++` 在请求成功后递增；失败不递增
- 与项目 UI：用库的 List/Card；三点与入场动画按本契约覆盖

## 3. Pull to refresh（下拉刷新）

**规格：** 做一个列表下拉刷新：在顶部下拉跟手，超过约 56–64px 阈值松手后触发刷新；刷新中顶部显示进度/三点；新数据就绪后从顶部接入（可短 fade），**不整页闪白**；刷新期间尽量保持下方已读内容稳定。

- 仅在 `scrollTop ≈ 0` 时接管下拉；与纵向滚动方向锁
- 跟手拉出 header；超阈值松手 → `refreshing`
- 成功：替换或 Diff 更新首屏数据；可选顶部短接入动画；**禁止**整页白屏重挂
- 失败：收起 header + 底部/顶部错误提示，列表仍在

## 4. Masonry fill（瀑布流补洞）

**规格：** 做一个瀑布流列表：多列高度不齐时，新卡片插入**当前最短列**；插入用短淡入（约 200–280ms），**禁止**为接新卡而重排整墙已有卡片位置。

- 列数按断点；每列独立文档流或绝对定位记账高度
- 新卡 → `argmin(columnHeights)`；只动新节点
- **Don't**：成功加载后把旧卡重新 `order` 一遍导致墙面抖动

---

## 5. Dual-column stagger（双列错峰入场）

**规格：** 做一个双列商品入场：同一批新卡按左→右或之字形顺序，列间错开 30–50ms 依次浮现（可叠传送带位移），形成错峰而非两列同时闪现。

- 顺序示例：L0, R0, L1, R1… 或 L0, L1, R0, R1（列内先）
- delay：`index * 30–50ms`；可叠加 #2 的 `-24px / 0.45s`
- 仅本批新卡；旧卡不动

---

## 6. Filter reload（筛选后重载）

**规格：** 做一个筛选/排序后的列表重载：变更筛选项后列表先短淡出，再换上**同构骨架**（复用 #1 光带契约），数据到后分块或整卡浮现；需要回顶时平滑滚到顶部，**不要**无动画瞬跳 + 白屏。

状态：`fading_out` → `skeleton` → `revealing` → `ready`  
回顶：`behavior: 'smooth'`（或减动效时 auto）  
保留筛选条/顶栏，只替换列表槽。

---

## 7. Tab keep-alive（Tab 切换保活）

**规格：** 做一个多 Tab 列表：切换 Tab 时用短淡切或局部骨架，**返回曾打开的 Tab 时恢复滚动位置与已加载页**，不重新从第一页清空重拉（除非业务强制刷新）。

- 每 Tab 缓存：`items`、`page`、`hasMore`、`scrollTop`
- 切走：记录 scrollTop；切回：还原后再显示
- 首访 Tab 可用 #1 骨架；再访不走首屏骨架除非 `stale`

---

## 8. Footer error bar（失败条不拆列表）

**规格：** 做一个分页加载失败态：预加载失败时在列表**底部**显示「加载失败 · 重试」，**不清空、不卸载**已成功渲染的商品；点重试仅重打失败页。

- 与 #2 footer 互斥：`loading` | `error` | `end`
- 重试成功 → 接 #2 传送带；再失败 → 仍留 error 条

---

## 9. Bottom-only skeleton（骨架只打新屏）

**规格：** 做一个分页骨架：加载下一页时**仅在底部约一屏**铺同构骨架（可带 #1 光带），上方已出现的真卡保持不动；数据到后底部骨架换成新卡（可用 #2 传送带）。

- 底部插入 2–4 个同构骨架卡（高度约一屏内）
- 真卡区域零改动 → 滚动位置天然稳定
- 成功：移除底骨架，append 真卡；失败：撤骨架，改 #8

## 10. Sticky category（粘性分类头）

**规格：** 做一个带分类的长列表：分类标题滚动时**吸顶**；点击顶部分类条时平滑滚动到对应锚点，吸顶态与当前分类高亮同步。

- 段头 `position: sticky; top: <nav高度>`
- 顶部分类 chip 点击 → `scrollIntoView` / 计算 offset 平滑滚
- `IntersectionObserver` 反推当前段，同步 chip 高亮

---

## 11. Back-to-top FAB（回顶）

**规格：** 做一个长列表回顶：滚动超过约两屏后显示回顶按钮；点击后平滑滚到顶部，**不触发**列表重载或清空。

- 显示条件：`scrollTop > 2 * clientHeight`
- 点击：只滚动；可与 #3 并存但回顶 ≠ 刷新

---

## 12. Hover prefetch（悬停预取详情）

**规格：** 做一个列表悬停预取：指针在卡片上停留约 200ms 后预取详情数据/路由；点击进入时应尽量秒开（已有缓存则直接用），移动端用 touch 长按或跳过预取。

- `pointerenter` 启动 200ms 计时；`leave` 取消
- 缓存按 id；失败静默，点击再走正常加载
- 移动端：可 `touchstart` 长按 ≥200ms，或仅靠点击加载
